상품팀이 Case 내용을 확인하고 판매를 허락할지 직접 결정합니다. 상품팀이 승인 의사결정 권한을 가지며, 별도 임계값·자동 판정 없이 상품팀 재량으로 판단합니다.

상품팀 결정: 이 조건으로 판매를 허락할까? Decision__c = 승인 / 조건부 승인 / 반려 → Status = 종료(Closed)
상품팀 결정 결과
✅ 승인 / 조건부 승인 판매 허가
상품팀 승인 결정 Decision__c = 승인 / 조건부 승인, 필요 시 Decision_Reason__c에 조건 입력.
상품팀 Case 종료 확정 후 Status = 종료(Closed).
시스템 RM에게 결과 통보 Slack으로 "판매 승인 완료" RM에게 알림.
⛔ 반려 판매 불가
상품팀 반려 결정 Decision__c = 반려, Decision_Reason__c에 반려 사유 입력.
상품팀 Case 종료 확정 후 Status = 종료(Closed).
시스템 RM에게 결과 통보 Slack으로 반려 결과와 Decision_Reason__c 사유를 함께 RM에게 알림.
최종 산출물
🧾 상품팀 결정 확정 → RM에게 통보
상품팀이 Decision__c(승인/조건부 승인/반려)를 확정하고 Status를 종료(Closed)로 바꾸면 요청한 RM에게 Slack으로 결과가 전달됩니다. 반려 시 Decision_Reason__c 사유가 함께 전달됩니다.

A Case 생성 자체 RM 수동 RM이 심사(Screening) 레코드타입으로 Case를 직접 생성 · 자동화 없음
B Case_Notify_ProductTeam Record-Triggered Flow Case 생성 시(after create) → 상품팀 Slack 채널에 Case 내용 게시 (고객·상품/금액·약정수익률·요청 RM·Case 링크)
C Case_Decision_Notify_RM Record-Triggered Flow Decision__c 확정 & Status = 종료(Closed) → 요청 RM에게 Slack 통보 (반려 시 Decision_Reason__c 포함)
D 기존 Case 필드 이미 존재 Agreed_Yield_Rate__c · Contract_Term_Months__c · Decision__c · Decision_Reason__c · Status · Priority — 신규 필드 추가 불필요

Slack 전송은 기존 SlackChannelMessageService(Invocable Apex) 재사용 · Opportunity는 사용하지 않음 · Case는 RM이 직접 생성(자동 생성 Flow 없음) · 별도 임계값/기준 없음 — 상품팀이 승인 의사결정권 보유.
